# Выявление банковских рисков в русскоязычных новостях

Дипломное исследование сравнивает классическое машинное обучение и mDeBERTa для анализа банковских новостей. Основная задача — бинарное выявление потенциального риска. Дополнительная задача — определение его категории.

Датасет содержит 5041 запись, 12 полей, 15 банков и 5 источников за 1999–2020 годы. Используется исходный `split`: 3535 записей train, 755 validation и 751 test. Положительных примеров соответственно 176, 40 и 38. SHA-256 исходного CSV: `52333a13e7fb6f6c4162486198fbf1d1ab368672a8974295995580a1924f67f3`.

## Основные результаты: бинарная классификация

| Модель | Validation F1 | Test F1 |
|---|---:|---:|
| LinearSVC | 0,7532 | 0,8642 |
| Logistic Regression | 0,7273 | 0,8861 |
| mDeBERTa | 0,7949 | 0,8649 |

Гиперпараметры, пороги и checkpoint выбирались по F1 положительного класса на validation. На test Logistic Regression показала более высокий F1 и Recall. Для рассматриваемого сценария мониторинга, в котором аналитики вручную проверяют предупреждения и приоритет отдан их точности, предпочтительной признана mDeBERTa.

| Модель | Test Precision | Test Recall | Ложные тревоги | Пропущенные риски |
|---|---:|---:|---:|---:|
| Logistic Regression | 0,8537 | 0,9211 | 6 | 3 |
| mDeBERTa | 0,8889 | 0,8421 | 4 | 6 |

Выбор mDeBERTa отражает прикладной приоритет Precision, а не универсальное превосходство Deep Learning. При высокой стоимости пропуска риска Logistic Regression может быть более подходящей. Разница составляет лишь две ложные тревоги на небольшом test и требует подтверждения на новых данных. Precision не являлась исходным критерием подбора.

## Дополнительное исследование: четыре класса

Классы: отсутствие риска (`no_risk`), киберриск (`cyber_risk`), операционный риск (`operational_risk`) и регуляторный риск (`regulatory_risk`). Основная метрика — Macro F1 по четырём классам; она не сравнивается напрямую с бинарным F1.

| Модель | Validation Macro F1 | Test Macro F1 |
|---|---:|---:|
| Logistic Regression `text_balanced` | 0,7446 | 0,8206 |
| mDeBERTa `text_standard`, seed 42 | 0,7500 | 0,7329 |

Для определения категории риска предпочтительна Logistic Regression. Дополнительные seed mDeBERTa дали validation Macro F1 0,7500 (42), 0,7338 (123) и 0,7565 (2026); среднее — 0,7468, выборочное стандартное отклонение — 0,0117. Устойчивое превосходство нейросети не установлено. В финальном test сохранена исходная модель seed 42.

## Порядок воспроизведения отчётов

Для локального анализа используется Python с зависимостями из `requirements.txt`. Ядро Jupyter должно иметь доступ к этим пакетам. Рабочий каталог — корень проекта с папками `data/` и `results/`.

```powershell
python -m pip install -r requirements.txt
python -m notebook
```

Последовательность аналитических отчётов: `00` → `03` → `07` → `11`. Они читают сохранённые результаты и не обучают классификаторы; `00` рассчитывает описательные TF-IDF-сходства. `00` и `11` сохраняют производные CSV отчётов. Для просмотра достаточно сохранённых таблиц и графиков.

Ноутбуки `01`, `02`, `05`, `06`, `08` содержат обучение и не входят в последовательность повторного исполнения отчётов. `09` и `10` содержат финальный инференс, уже выполненный ранее. Повторное тестирование для чтения и проверки отчётов не требуется. В обоих протоколах установлено `RUN_FINAL_TEST=False`. Их сохранённые output относятся к завершённым запускам с включённым test; флаг отключён после завершения оценки.

Для исходной среды Kaggle используются `torch`, `transformers`, `accelerate`, `sentencepiece`, `safetensors` и GPU. Веса mDeBERTa в локальный проект не включены: основная многоклассовая модель хранится в Kaggle `notebook80586b8724`, повторы — в `notebook1d4179b110`; путь бинарной модели указан в ноутбуке 03. Для отчётов эти веса не нужны. Полная воспроизводимость GPU-запусков требует исходных внешних артефактов и совместимой среды; зависимости не зафиксированы до точных версий.

## Ограничения

Сильный дисбаланс, небольшие положительные классы и исторический период данных ограничивают обобщение. В test всего четыре регуляторных примера. Возможны смысловые повторы между выборками, несмотря на разделение групп событий. Бинарный test ранее анализировался, поэтому его нельзя считать новым независимым подтверждением. Финальные конфигурации многоклассовой части фиксировались по validation; дальнейший подбор по test не проводился. Совпадение сохранённых результатов не заменяет проверку на новом временном наборе.

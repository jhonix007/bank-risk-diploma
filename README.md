# Выявление банковских рисков в русскоязычных новостях

Дипломный проект посвящён классификации русскоязычных банковских новостей с помощью классических методов машинного обучения и mDeBERTa. Основная задача — бинарное определение наличия потенциального банковского риска в новости. Дополнительная задача — определение категории риска.

Использованные модели: Logistic Regression, LinearSVC и mDeBERTa (`microsoft/mdeberta-v3-base`). Основной выполненный ноутбук — [bank_risk_diploma.ipynb](bank_risk_diploma.ipynb). Он содержит EDA, обучение моделей, validation и test, проверку устойчивости по seed, графики и заключение.

## Данные

[Датасет](data/bank_risk_dataset.csv) содержит 5 041 запись. Текст новости хранится в `text_fragment`, заголовок — в `title`, банк — в `entity_norm`. Целевая переменная `alert_flag` задаёт наличие риска (0/1), а `risk_type_4cls` — один из четырёх классов: `no_risk`, `cyber_risk`, `operational_risk`, `regulatory_risk`.

Разделение фиксировано исходным полем `split`: train — 3 535 записей, validation (`valid`) — 755, test — 751. Положительных примеров соответственно 176, 40 и 38. Параметры моделей, checkpoint и бинарные пороги выбираются по validation; test служит для итоговой оценки.

SHA-256 исходного CSV: `52333a13e7fb6f6c4162486198fbf1d1ab368672a8974295995580a1924f67f3`.

## Результаты полного Kaggle-запуска

Значения сверены с сохранёнными output основного ноутбука. Для бинарной задачи приводится F1 положительного класса, для многоклассовой — Macro F1 по четырём классам.

| Модель | Validation F1 | Test F1 |
|---|---:|---:|
| Logistic Regression | 0.7273 | 0.8861 |
| LinearSVC | 0.7532 | 0.8642 |
| mDeBERTa | 0.7671 | 0.8378 |

| Модель | Validation Macro F1 | Test Macro F1 |
|---|---:|---:|
| Logistic Regression (text) | 0.7446 | 0.8206 |
| Logistic Regression (bank context) | 0.7381 | 0.8241 |
| mDeBERTa | 0.7512 | 0.8417 |

Проверка устойчивости mDeBERTa на validation:

| Seed | Бинарная задача, F1 | Многоклассовая задача, Macro F1 |
|---|---:|---:|
| 42 | 0.7671 | 0.7512 |
| 123 | 0.7556 | 0.5537 |
| 2026 | 0.7778 | 0.7372 |

В бинарной задаче mDeBERTa показала лучший Validation F1, но Logistic Regression превзошла её по Test F1 и Recall (0.9211 против 0.8158). Преимущество нейросети по Precision на test небольшое: 0.8611 против 0.8537, или пять ложных предупреждений против шести при семи пропущенных рисках против трёх. Применение mDeBERTa для снижения ложных предупреждений может быть оправдано только при соответствующих практических требованиях.

В дополнительной многоклассовой задаче mDeBERTa показала лучший Test Macro F1, однако проверка разных seed выявила существенную нестабильность. Устойчивое превосходство глубокого обучения над классическими методами не установлено. Дисбаланс классов, небольшое число рисковых примеров и исторический период данных ограничивают обобщение результатов.

## Просмотр и воспроизведение

Сохранённые таблицы и графики доступны при просмотре основного ноутбука без исполнения ячеек. Для локального просмотра подходит Jupyter Notebook с зависимостями из `requirements.txt`.

Полное обучение mDeBERTa выполнялось в Kaggle с GPU Tesla T4. Ноутбук ищет единственный `bank_risk_dataset.csv` внутри `/kaggle/input` и записывает артефакты в `/kaggle/working/bank_risk_diploma/`. Для воспроизведения исходный файл из `data/` подключается как Kaggle Input; локальный путь `data/bank_risk_dataset.csv` автоматически не используется. Код ноутбука сохранён без изменений, включая включённые `RUN_SEED_CHECK` и `RUN_FINAL_TEST`: полное исполнение повторяет обучение и финальную оценку.

Сохранённое окружение: Python 3.13.15, PyTorch 2.11.0+cu128. Установка в ноутбуке задаёт `transformers==4.57.3`, `accelerate>=1.0,<2`, `sentencepiece>=0.2`, `safetensors>=0.4`. Эти ограничения отражены в `requirements.txt`; PyTorch указан по сохранённой базовой версии 2.11.0, сборка CUDA выбирается отдельно для GPU-среды. Существующие нижние границы версий аналитических библиотек сохранены. Полный набор версий окружения не сохранён, поэтому файл зависимостей не является точной фиксацией Kaggle-среды. Локальное выполнение всего ноутбука требует GPU, подготовки зависимостей и адаптации путей.

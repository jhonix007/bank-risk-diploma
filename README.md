# Классификация банковских рисков в новостях

Дипломное исследование сравнивает классические методы машинного обучения и mDeBERTa на русскоязычных банковских новостях. Основная задача — обнаружить потенциальный риск, дополнительная — определить его категорию.

[Основной ноутбук](bank_risk_diploma.ipynb) полностью выполнен в Kaggle: сохранены 12 обучений mDeBERTa, таблицы, графики, статистические сравнения, анализ ошибок и итоговые выводы. Его можно изучать без повторного запуска.

## Данные и модели

[Датасет](data/bank_risk_dataset.csv) содержит 5 041 запись. Поле `alert_flag` задаёт наличие риска, `risk_type_4cls` — класс: `no_risk`, `cyber_risk`, `operational_risk` или `regulatory_risk`.

Исходное разбиение фиксировано: train — 3 535, valid — 755, test — 751. Связанные новости учитываются по `event_group_id`. Признаки строятся из текста, заголовка и названия банка; `found_risk_keywords` исключён из-за возможной связи с разметкой.

Использованы DummyClassifier, обучаемый словарный baseline, Logistic Regression и LinearSVC с TF-IDF, а также `microsoft/mdeberta-v3-base`. Словарный baseline применяется в бинарной задаче.

## Методика

Train разделён по событийным группам: 2 119 строк для обучения, 708 для выбора checkpoint и конфигурации, 708 для бинарного порога. Классические гиперпараметры выбираются групповой кросс-валидацией внутри обучающей части. У бинарной mDeBERTa checkpoint выбирается по Average Precision без настройки порога по эпохам; затем порог настраивается отдельно по F1. В многоклассовой задаче критерий — Macro F1.

Valid и test не участвуют в настройке. Основной seed — 42, устойчивость проверяется на seed 42, 123 и 2026. Неопределённость оценивается парным bootstrap событийных групп с 95%-ми интервалами.

## Основные результаты

Вход основной mDeBERTa — полный текст (`text`), выбранный по stop-выборке. Ниже приведены результаты seed 42.

| Модель | Valid F1 | Test F1 | Test Precision | Test Recall |
|---|---:|---:|---:|---:|
| Logistic Regression | 0.6667 | 0.7955 | 0.7000 | 0.9211 |
| LinearSVC | 0.6567 | 0.8533 | 0.8649 | 0.8421 |
| mDeBERTa | 0.7013 | 0.8684 | 0.8684 | 0.8684 |

| Модель | Valid Macro F1 | Test Macro F1 |
|---|---:|---:|
| Logistic Regression | 0.7550 | 0.7973 |
| LinearSVC | 0.5709 | 0.6445 |
| mDeBERTa | 0.6083 | 0.6013 |

На test mDeBERTa получила наибольший наблюдаемый бинарный F1, но 95%-й интервал разности F1 с Logistic Regression включает ноль: [−0.0281; 0.1880]. Статистическое преимущество нейросети не подтверждено. Logistic Regression имеет более высокий Recall, а LinearSVC остаётся сильной альтернативой по F1 и точности предупреждений.

В многоклассовой задаче test-интервал разности Macro F1 mDeBERTa − Logistic Regression равен [−0.3183; −0.0627] и поддерживает преимущество Logistic Regression для этих моделей и этой выборки. Универсальное превосходство глубокого обучения не установлено.

## Абляция и устойчивость

Сравниваются `text_without_title`, `text` и `bank_context`. Заголовок надёжно удаляется у 4 926 записей; остальные 115 сохраняются без изменений. Строгая абляция использует общее подмножество: 741 строку valid и 734 строки test.

На этом подмножестве полный текст имеет более высокий AP, чем вариант без заголовка, во всех трёх seed на обеих выборках. По F1 он лучше в двух из трёх запусков на valid и во всех на test. Все valid-интервалы разности F1 между входами включают ноль; устойчивого статистического подтверждения эффекта нет. Банковский контекст также не дал стабильного выигрыша.

| Seed | Бинарный Valid F1, text | Многоклассовый Valid Macro F1 |
|---|---:|---:|
| 42 | 0.7013 | 0.6083 |
| 123 | 0.6593 | 0.2432 |
| 2026 | 0.6667 | 0.5361 |

Многоклассовая нейросеть заметно зависит от seed. Для этой задачи результаты скорее поддерживают Logistic Regression. Выбор модели мониторинга должен учитывать одновременно пропущенные риски, ложные предупреждения и вычислительные затраты.

## Ограничения

В test всего 38 рисковых новостей, включая четыре регуляторных. Малые классы, дисбаланс и возможные повторы текстов ограничивают надёжность и обобщение оценок. Тестовая выборка уже использовалась в предварительных экспериментах и не является полностью независимым подтверждением. Для проверки переноса на новые новости и периоды нужны новые размеченные данные.

## Структура и запуск в Kaggle

```text
.
├── bank_risk_diploma.ipynb
├── README.md
├── requirements.txt
├── .gitignore
├── .gitattributes
└── data/
    └── bank_risk_dataset.csv
```

Для полного воспроизведения нужен Kaggle с совместимым CUDA GPU и включённым Internet:

1. Импортировать `bank_risk_diploma.ipynb` и подключить исходный CSV как Kaggle Input.
2. Включить GPU и Internet. Зависимости устанавливаются первыми ячейками; PyTorch используется из GPU-среды Kaggle. Описание библиотек находится в [requirements.txt](requirements.txt); нужен Python 3.11 или новее.
3. Выполнить `Run All`. Профиль `FULL` включает 12 обучений mDeBERTa, `CORE` — четыре без проверки устойчивости. Эффективный batch сохраняется при поддерживаемом числе GPU.

Результаты записываются в `/kaggle/working/bank_risk_diploma_final/`. Для продолжения в новой сессии сохранённый Output подключается как Input и указывается в `RESUME_OUTPUT_SOURCE`. Совместимые завершённые обучения восстанавливаются после проверки; прерванное обучение начинается заново. Длительность и возможность завершить FULL за одну сессию зависят от доступных ресурсов.

Веса моделей и отдельный Kaggle Output в репозиторий не включены. Новые запуски могут отличаться от сохранённого; заключение относится к представленным результатам.
